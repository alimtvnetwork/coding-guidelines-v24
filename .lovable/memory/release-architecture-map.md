## 3. How Version Propagates (Sync Pipeline)

Running 
pm run sync triggers five core synchronization scripts in sequence:

1. **scripts/sync-version.mjs**:
   Reads package.json, ersion-authors.json, and scripts/prompt-sync-config.json. Emits root ersion.json.
2. **scripts/sync-spec-tree.mjs**:
   Walks spec/ markdown files, extracts titles/versions from frontmatter, emits src/data/specTree.json.
3. **scripts/sync-health-score.mjs**:
   Computes spec completeness, rule coverage, and audit health score, emits public/health-score.json.
4. **scripts/sync-readme-stats.mjs**:
   Stamps versions, folder counts, file counts, and update timestamps into eadme.md and docs/*.md.
5. **scripts/sync-guidelines.mjs**:
   Mirrors spec/17-consolidated-guidelines/31-compiled-simple-coding-guidelines.md to .cursorrules and .lovable/coding-guidelines/coding-guidelines.md.

## 4. Release Ceremony Flow

A complete release follows these strict steps:

1. **Pre-flight**:
   - Check git status (clean state required).
   - Run git pull to ensure local branch is in sync with upstream.
   - Verify version bump tier (e.g. MINOR: 6.23.0 -> 6.23.0).
2. **Bumping**:
   - Run 
ode scripts/release.mjs --tier minor --scope "<headline>" --skip-slides.
   - Updates package.json, runs 
pm run sync, prepends changelog.md and spec/19-main-worker-service/98-changelog.md.
3. **Drift Verification**:
   - Run 
ode scripts/sync-check.mjs --fix to verify 0 drift across all 7 sync-managed files.
4. **Commit, Tag & Push**:
   - git commit -m "release: vX.Y.Z <headline>"
   - git tag vX.Y.Z
   - git push && git push origin vX.Y.Z

## 5. Bundle Installer Integration

When downstream repositories run any bundle installer (*-install.sh or *-install.ps1):
- ersion.json is smart-merged into the target's ersion.json under codingGuideline.
- .lovable/memory/ and .lovable/what-to-read.md are copied into the target repo, transferring this architectural knowledge directly.
